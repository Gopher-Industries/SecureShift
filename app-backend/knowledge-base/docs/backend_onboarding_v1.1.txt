SecureShift backend onboarding - current handover

The filename retains the historical v1.1 identifier. Earlier PDF-extracted setup
commands are superseded by this guide and the canonical repository-root README.md.
This is one monorepo, with app-backend, app-frontend/employer-panel,
app-frontend/admin-panel, and guard_app.

1. Full-stack first-time setup

Use Docker with the Compose plugin. On Windows enable WSL2 integration. Run from
the repository root; no private credentials or backend .env file are required.
If port 5000 is occupied, copy the root .env.example to .env and set
BACKEND_HOST_PORT=5001. Do not overwrite an existing .env.

docker compose up --build -d
docker compose ps -a
docker compose logs ollama-models ai-indexer

All eight services: backend, mongodb, mailpit, frontend-employer, frontend-admin,
ollama, ollama-models, ai-indexer. The last two are one-shot jobs: Exited (0)
means success. Wait for successful model download and indexing.

After successful indexing, ensure the backend loads the regenerated vectors:

If the backend is already running:
docker compose restart backend

If the backend is not currently running:
docker compose up -d backend

Check backend health:
curl http://localhost:5000/api/v1/health

Default host ports: backend 5000 (or configured override such as 5001), employer
3000, admin 3001, MongoDB 27017, Mailpit SMTP 1025 and inbox 8025.
Swagger: http://localhost:5000/api-docs
Mailpit: http://localhost:8025

2. AI readiness and indexing

Compose Ollama is internal at http://ollama:11434, not published to the host.
Required models: nomic-embed-text:latest (embeddings), llama3.2:latest (answers).
The backend waits for MongoDB and Mailpit health, not AI indexing. Backend HTTP
200 does not guarantee AI/index readiness. Vectors load at backend startup.

The indexer reads all TXT sources in app-backend/knowledge-base/docs:
backend_onboarding_v1.1.txt
onboarding.txt
guard_app_onboarding.txt

After source updates, run from the repository root:

docker compose run --rm ai-indexer

After successful indexing, ensure the backend loads the regenerated vectors:

If the backend is already running:
docker compose restart backend

If the backend is not currently running:
docker compose up -d backend

Output: matching JSON files in app-backend/knowledge-base/vectors. Regeneration
for this documentation cleanup is deferred until review.

3. Host backend development

Use Node >=22.13.0 and npm ci. Runtime validation was recorded at Node v22.13.1.
From the repository root, stop any Compose backend occupying the same port:

docker compose stop backend
docker compose up -d mongodb mailpit

On first setup only:

cp app-backend/.env.example app-backend/.env
cd app-backend
npm ci
npm run dev

The template supplies local development values, including Mailpit. For an
occupied port 5000, set PORT=5001 in app-backend/.env and adjust client URLs.
Host processes and Compass use localhost; containers use the service name mongodb.
Host/Compass URI (adjust the port if overridden):
mongodb://secureshift_app:secureshift_app_password@localhost:27017/secureshift_local?authSource=secureshift_local
Compose URI:
mongodb://secureshift_app:secureshift_app_password@mongodb:27017/secureshift_local?authSource=secureshift_local

Host Mailpit: SMTP_HOST=localhost, SMTP_PORT=1025, SMTP_SECURE=false,
SMTP_AUTH_REQUIRED=false, EMAIL_ENABLED=true, SMTP_FROM_EMAIL=local@example.test.
Leave SMTP_USER and SMTP_PASS empty. Compose uses SMTP_HOST=mailpit instead.
Read OTP messages in the Mailpit inbox; disabling email provides no OTP fallback.
Host AI requires a separately reachable Ollama server, OLLAMA_HOST, and both
models. Starting Compose does not automatically provide host AI access.

4. Normal local seed data

From the root for Compose:

docker compose run --rm -e SEED_ALLOW_LOCAL=true backend npm run seed

For a host backend, temporarily set SEED_ALLOW_LOCAL=true in app-backend/.env,
run npm run seed from app-backend, then restore SEED_ALLOW_LOCAL=false.
Seeding updates deterministic local records and does not bypass employer/guard OTP.
See app-backend/README.md for the complete account table. Local-only password:
SecureShift1!; admin: admin.local@secureshift.test; employer: ops.local@secureshift.test;
approved guard: mia.guard@secureshift.test.

5. Destructive resets - not normal onboarding

npm run seed:reset deletes known seeded records only, does not repopulate them,
and requires SEED_ALLOW_LOCAL=true plus SEED_RESET_CONFIRM=SecureShiftLocalReset.
Use the separate reset commands in app-backend/README.md only intentionally.

WARNING: docker compose down -v deletes MongoDB data, downloaded Ollama models,
and uploads. It is not routine cleanup. Back up needed data before a full reset.
Historical note: old MongoDB volumes can retain old users because initialization
scripts do not rerun on existing volumes. Diagnose credentials before resetting;
fresh clones do not need a reset. MongoDB image upgrades are separate tested work.

6. Daily restart and checks

From the root:

docker compose up -d
docker compose ps -a

If indexing ran again, check its success and use the restart/start commands in
section 2 to load regenerated vectors.
Normal shutdown preserves data, models and uploads:

docker compose down

For host backend development, start mongodb and mailpit in Compose, then run
npm run dev from app-backend. The stable backend CI command is npm run test:ci:
5 suites, 91/91 tests passing in the handover snapshot, not a fresh test run.

Troubleshooting: EAI_AGAIN mongodb on the host means the database URI needs
localhost. Missing OTP: check Mailpit and email configuration, not private SMTP
credentials. Empty collections may indicate an unseeded or different database.
Keep .env files private and encryption keys stable for existing encrypted data.
