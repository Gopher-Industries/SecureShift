SecureShift Guard App onboarding - current handover

The root README.md is the canonical full-stack quickstart; guard_app/README.md
covers mobile development. Earlier version 1.0 instructions are superseded.
This is one monorepo: app-backend, app-frontend/employer-panel,
app-frontend/admin-panel, and guard_app. The mobile app runs outside Compose.

1. Backend and local services

Use Docker with Compose. From the repository root, on first setup:

docker compose up --build -d
docker compose ps -a
docker compose logs ollama-models ai-indexer

No private credentials or backend .env are required for ordinary local Compose.
All eight services: backend, mongodb, mailpit, frontend-employer, frontend-admin,
ollama, ollama-models, ai-indexer. The last two are one-shot jobs; Exited (0)
means success.

After successful indexing, ensure the backend loads the regenerated vectors:

If the backend is already running:
docker compose restart backend

If the backend is not currently running:
docker compose up -d backend

Backend: http://localhost:5000/api/v1/health
Swagger: http://localhost:5000/api-docs
Employer panel: http://localhost:3000
Admin panel: http://localhost:3001
MongoDB: localhost:27017
Mailpit SMTP: localhost:1025; inbox: http://localhost:8025

Use BACKEND_HOST_PORT=5001 in the optional root .env if port 5000 is occupied,
and adjust client URLs. No volume reset is needed for a fresh clone.

2. AI readiness

Models: nomic-embed-text:latest and llama3.2:latest. Compose Ollama is not
published to the host. Host AI requires a separately reachable Ollama server.
Backend HTTP 200 does not guarantee AI/index readiness; the backend does not
wait for indexing and loads vectors at startup. All three indexed TXT sources
in app-backend/knowledge-base/docs are backend_onboarding_v1.1.txt,
onboarding.txt, and guard_app_onboarding.txt. After source changes, run:

docker compose run --rm ai-indexer

After successful indexing, ensure the backend loads the regenerated vectors:

If the backend is already running:
docker compose restart backend

If the backend is not currently running:
docker compose up -d backend

Regeneration for this documentation cleanup is deferred until review.

3. Run the Guard App

Guard App mobile tooling requires Node >=20.19.4. Node 22.13+ is compatible and
a convenient shared local version for backend development; the backend requires
Node >=22.13.0. Use npm and Expo Go on your phone, or Android Studio / Xcode
for an emulator or simulator. From the root:

cd guard_app
npm ci
npm start

Select Expo Go (press s if needed), then scan the QR code. Alternatives, run
separately: npm run android, npm run ios (macOS), npm run web.

Set guard_app/.env to a reachable backend address for your device, for example:

EXPO_PUBLIC_API_BASE_URL=http://192.168.1.10:5000

Replace the IP with your computer's LAN address. Android emulator can use
http://10.0.2.2:5000. Use 5001 if configured. Do not append /api/v1; the app adds
it. Restart Expo after environment changes. Physical devices need network
access; check host/WSL forwarding and firewalls if connection fails.

4. Accounts and email

Use local fixtures documented in app-backend/README.md or register a guard and
follow the approval flow. Sign out of any previous session to use another account.
Employer and guard OTP messages are captured by Mailpit at http://localhost:8025
on your computer. No private SMTP credentials are required. Disabling email does
not expose an OTP fallback. Normal seed and destructive reset commands are
separate in the backend README; reset is not an onboarding step.

5. Daily development

From the repository root:

docker compose up -d
docker compose ps -a

After successful indexing, use the restart/start commands in section 2 to load
regenerated vectors. Run npm start from guard_app.
Normal shutdown preserves data, models, and uploads:

docker compose down

WARNING: docker compose down -v deletes MongoDB data, downloaded Ollama models,
and uploads. It is not routine cleanup.

For a host backend, follow ENVIRONMENT_SETUP.md: Node >=22.13.0, npm ci, MongoDB
and Mailpit in Compose. Runtime validation was recorded at Node v22.13.1;
backend npm run test:ci covered 5 suites, 91/91 passing in the handover snapshot.
Guard App checks: npm run lint, npm run typecheck, npm run test:ci.
Confirm the team's current branch/PR target before contributing.
